# 彩雲 / Saiun 公開手順

公開先は`Nanashisan6400/saiun`に固定しています。このツールはリポジトリ作成、Force Push、ブランチ削除を行いません。

## 開始コマンド

開発フォルダ（ebookproject）または公開ソースのリポジトリ直下で実行します。

```sh
python3 publish_saiun.py --check --offline  # 認証不要の公開候補/秘密情報検査
python3 publish_saiun.py --check            # 履歴検査と差分表示。Commit/Pushなし
python3 publish_saiun.py                    # 確認後だけCommit/Push
```

毎回、差分を確認し、端末へ正確に`PUBLISH`と入力した場合に限りCommit/Pushします。自動承認オプションはありません。入力を変える、EOF、Ctrl+Cで中止できます。Push途中の通信断や中断ではサーバー側で完了している可能性があるため、GitHub側の結果も確認してください。

コミット名義が既存Git設定にない場合は、今回限りの名義を指定します。

```sh
python3 publish_saiun.py --name '公開用の名前' --email 'GitHubで使用するメール'
```

名義を開発フォルダへ保存しません。メールは公開コミットに記録されるため、必要ならGitHubのnoreplyアドレスを使用してください。

## 初回のリポジトリ作成

公開先は現在未作成です。GitHubでNanashisan6400としてログインし、所有者Nanashisan6400、名前saiunの空のリポジトリを作成してください。README、.gitignore、LICENSEの自動追加はすべてオフにします。これらは公開ツールで配置します。公開リポジトリにする場合はPublicを選択してください。

公開ツール自身はリポジトリを作成しません。空のリポジトリを作成した後、`python3 publish_saiun.py --check`で確認します。

## 認証

既存のGit HTTPS認証ヘルパーを使用し、トークンをソースに保存しません。認証できない場合は処理を停止します。公開先や認証値をURL引数で受け付けません。

GitHub CLIを利用する場合は、公式手順で`gh`を導入してから別操作で`gh auth login`、`gh auth setup-git`を実行できます。このスクリプト自身は認証設定やリポジトリ作成を行いません。GitのURL書換え設定がある場合は、意図しない宛先へ送らないよう停止します。

## 公開対象

`publishing/manifest.json`の各ファイルを明示した許可リストだけを使用します。フォルダ全体のコピーや`git add .`は行いません。Ubuntuコードの配置は公開先のみ`ubuntu/ubuntureader/`とし、開発側の配置を変更しません。

実書籍/合成EPUB、表紙、DB、位置、ログ、結果画像、ビルド物、キャッシュ、試用版、開発用バックアップ、server、HANDOFF、AGENTS、開発専用資料は含めません。テストの合成入力は実行時に一時領域へ生成します。IPAex原本とライセンスは同梱します。将来のiPad実装は別途許可リストへ追加します。

秘密らしいキー/トークン/パスワード等は値を表示せず、ファイル名・行番号・検出種別だけを表示して停止します。これはパターン検査と許可リストの組み合わせであり、あらゆる秘密の不在を保証するものではありません。差分も必ず目視してください。未知のバイナリ、リンク、禁止拡張子は公開しません。フォントは公式原本のハッシュも検査します。

## リモートの保護

- 空のリポジトリだけを初回公開の対象にします。初期README等がある初回リポジトリも、自動上書きせず停止します。
- 2回目以降は`.saiun-publication.json`の一覧/内容/モードと公開コミットの識別行を確認します。リモートだけのファイル、削除、内容変更、公開ツール以外のコミットを検出すると停止します。
- ローカルで許可リストから外したファイルも、GitHubに残っていれば停止します。通常の確認入力を理由にまとめて削除しません。削除や初回の既存内容の引継ぎが必要な場合は、別途の明示的な確認・設計が必要です。
- 公開識別行は運用上の識別であり、暗号署名による改ざん証明ではありません。GitHubアカウント管理の代わりにはなりません。
- 既定ブランチの全履歴と他ブランチの履歴を取得しますが、公開するのは既定ブランチだけです。他ブランチやタグは変更しません。既定ブランチが未作成の空リポジトリでは`main`を使います。
- 確認後にローカルの再検査とリモートHEADの再確認を行います。その後に競合更新があっても、通常のFast-forward検査によりPushが拒否されます。自動再試行・Force Pushはしません。
- GitHubのコードやスクリプトを実行せず、開発ソースへ取り込みません。グローバルGitフック/テンプレート/属性ファイルは公開処理へ取り込まず、改行コードも自動変換しません。

## 一時領域と後始末

GitはOSの一時領域の`saiun-publish-*`内だけで使います。開発側に`.git`がある場合は場所を報告して停止し、削除しません。Git履歴や公開状態を開発側へ保存しません。公開状態の記録はGitHub側に置きます。

成功、エラー、キャンセル、Ctrl+C、SIGTERMでは終了処理で一時領域を削除します。SIGKILL、電源断、OS障害では終了処理を実行できないため、即時削除を保証できません。残った一時フォルダはGit履歴を含むため、OSの一時領域を確認し、実行中でないことを確かめてから手動で削除してください。他のフォルダを自動削除する機能は設けません。

## ローカルの動作検証

```sh
python3 -m unittest publishing.tests.test_publisher
```

検証用GitリポジトリはすべてOSの一時領域で作成・削除します。GitHubへ接続/Pushしません。本番リモートを変更するCLIオプションはありません。


この公開ツールは`.git`を含む通常のcloneフォルダでも停止します。公開ソースから実行する場合はZIP展開等のGit管理情報のないコピーを使ってください。既存の`.git`をツールが削除することはありません。Readerそのものの起動にはこの制限はありません。
